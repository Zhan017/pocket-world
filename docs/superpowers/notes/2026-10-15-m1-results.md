# Claude World M1 results (Hyundai frame)

Run on 2026-10-15 with the local dev server (`node tools/dev-server.mjs`), `http://localhost:3000/?plan=1`,
frame `tools/fixtures/crossing-clean.jpg` (1688 x 1070, overlays removed by hand), model `claude-opus-5-5`,
effort `high`, adaptive thinking. Branch `claude-world-m1`.

## First attempt failed: structured outputs can't hold the plan schema

The first run stopped after 29 s with Anthropic's 400 "The compiled grammar is too large, which would cause
performance issues". Probes showed every element schema compiles on its own (vehicles, objects, markings,
surfaces, materials), the legacy scene schema compiles, but the full plan schema, the full patch schema, and
the plan without vehicles or without objects all fail. The fix (commit f1f97d3) sends each schema as a
non-strict tool (`submit_plan`, `submit_patch`, `tool_choice: auto`) instead of `output_config.format`;
`validatePlan` stays the guard. Probe and the real run both returned complete objects through the tool.

## Against the spec's success criteria (milestone 1 scope)

1. **Start view matches the frame: met.** Pixel-identical at the start pose.
2. **Believable 360° continuation, no invented near-field structures: met for layout, partly for look.**
   The road network, verges, median and crossing continue coherently behind the camera; nothing invented
   overhead. Away from the photo it is stylised (tiles, flat far ground) — the Marble far field (milestone 4)
   and better material variation are the planned answers.
3. **Walk at street level with collision: not in M1 scope.** You can move anywhere within 0.6 x extent;
   collision and the step-down from 6 m are milestone 2.
4. **The Hyundai as a 3D car you can walk behind: met.** Claude identified it as a Hyundai Creta and the
   existing car builder produced a model with a back and tail lights; position looks about right.
5. **Overlays: not in M1 scope** (the frame was cleaned by hand; milestone 3).
6. **Under ~15 minutes with a preview first: met.** 2.7 minutes; the 2.5D preview shows after the scan.

## Problems found

- **Structured-output grammar limit** (fixed in f1f97d3, see above).
- **Views show the car's flat cutout, not its 3D model,** whenever the main camera sits at the photo's pose:
  the cutout/model cross-fade and the people billboards follow the main camera, not the view camera
  (`world.update` is driven by the page camera). Claude then sees a flat car in the look-back view.
- **Paint is blocky up close:** flat-colour noise uses 33 cm cells (`hash(floor(xz * 3))` in scenebuild).
- **Tiles repeat visibly** at mid distance (mirrored 2 to 3 m tiles over large verges).
- **Far ground is a flat colour disc** meeting the sky in a straight line.
- **The camera estimate never changed** (6 m, 25°); Marble estimated 4.4 m for the same frame earlier. Both
  give a matching start view (projection), so the difference only shows as world scale. Worth a check in M2
  with the walking eye height.
- Claude declared itself done after 2 rounds; the blend view showed nothing misaligned in the photo's field
  of view, which is expected since the photo is projected onto the geometry. Alignment errors show up off-axis,
  so the look-back and map views carry most of the correction signal.

## Recommendation

**Go for milestone 2**, with these first:

1. Drive the world's per-camera updates (car cutout/model fade, billboards) from each view camera inside
   `renderViews`, so Claude sees the 3D car in the map and look-back views.
2. Smooth the flat-colour noise and break tile repetition (larger tiles plus a low-frequency tint variation).
3. Then M2 as planned: cars and people placed from the plan (`at`), collision walking, the step-down from the
   camera height to the street.

Cost and time leave plenty of room: at $0.46 and under 3 minutes per frame there is budget for a higher
effort setting or more correction rounds if quality needs it.
